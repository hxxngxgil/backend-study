# Exception Handling (예외 처리)

## 예외 처리가 필요한 이유

프로그램 실행 중에는 다양한 오류 상황이 발생할 수 있다.

예시

- 네트워크 연결 실패
- 파일 없음
- 데이터베이스 오류
- 사용자 입력 오류

예외 처리가 없으면 프로그램이 비정상 종료될 수 있다.

---

## 반환값으로 예외 처리

예외 처리 기능이 없을 경우

반환값을 통해 오류 여부를 전달할 수 있다.

예시

- 성공 → true
- 실패 → false

문제점

- 정상 흐름과 오류 흐름이 섞임
- 오류 원인 파악 어려움
- 코드 복잡도 증가

---

# 자바 예외 처리

## 예외 계층

모든 예외는 Throwable을 상속받는다.

Throwable

├ Exception
│ ├ RuntimeException
│ └ 기타 체크 예외
│
└ Error

---

## Error

시스템 수준 오류

예시

- OutOfMemoryError

개발자가 복구하기 어렵다.

보통 처리하지 않는다.

---

## Exception

애플리케이션에서 처리 가능한 예외

---

## 예외 처리 기본 규칙

예외가 발생하면

1. catch로 처리
2. 처리하지 못하면 throws로 던짐

처리 가능한 곳까지 계속 전파된다.

---

# 체크 예외 (Checked Exception)

컴파일 시점에 확인되는 예외

반드시 처리해야 한다.

예시

IOException

---

## 특징

- try-catch 필요
또는
- throws 선언 필요

---

## 장점

예외 누락 방지

---

## 단점

코드가 복잡해질 수 있음

---

# 언체크 예외 (Unchecked Exception)

RuntimeException 계열

컴파일러가 강제하지 않는다.

예시

- NullPointerException
- IllegalArgumentException

---

## 특징

처리하지 않아도 컴파일 가능

---

## 실무에서 언체크 예외를 많이 사용하는 이유

모든 예외를 처리하는 것은 현실적으로 어렵다.

예시

- 네트워크 장애
- 외부 시스템 장애

어플리케이션이 해결할 수 없는 경우가 많다.

그래서

중요한 비즈니스 예외만 체크 예외를 사용하고

나머지는 RuntimeException 기반으로 처리하는 경우가 많다.

---

# 예외 처리 도입

## 예외 복구

문제가 발생해도 다시 정상 상태로 복구

예시

재시도

---

## 정상 흐름과 예외 흐름 분리

정상 로직

예외 로직

을 분리할 수 있다.

코드 가독성이 좋아진다.

---

## 리소스 반환 문제

파일

네트워크

DB 연결

등은 사용 후 반드시 반환해야 한다.

반환하지 않으면

리소스 누수가 발생한다.

---

# finally

예외 발생 여부와 관계없이

항상 실행되는 블록

예시

try {
}
catch(Exception e) {
}
finally {
}

---

## 사용 목적

리소스 정리

연결 종료

파일 닫기

---

# 예외 계층 활용

공통 부모 예외를 만들 수 있다.

예시

AppException

├ NetworkException
├ DatabaseException
└ BusinessException

---

## 장점

- 공통 처리 가능
- 예외 관리 용이

---

# 실무 예외 처리 전략

실무에서는 모든 예외를 직접 해결하지 않는다.

예시

상대 서버 네트워크 선이 끊어짐

→ 우리 프로그램이 해결 불가능

---

## 일반적인 처리 방식

1. 필요한 경우 예외 발생
2. 계속 상위로 전파
3. 최종 진입점(Main, Controller 등)에서 공통 처리

---

## 사용자

간단한 오류 메시지 제공

예시

"일시적인 오류가 발생했습니다."

---

## 개발자

상세 로그 기록

예시

- 발생 위치
- 예외 메시지
- 스택 트레이스

빠른 원인 분석 가능

---

# try-with-resources

AutoCloseable을 구현한 객체를 자동으로 정리한다.

예시

try(Resource resource = new Resource()) {

}

---

## 장점

### 자동 자원 해제

close() 자동 호출

---

### 리소스 누수 방지

모든 자원이 안전하게 정리됨

---

### 코드 간결

finally 작성 불필요

---

### 가독성 향상

정리 코드 감소

---

### 스코프 최소화

리소스 사용 범위가 명확해짐

---

### 빠른 자원 반환

사용 즉시 자원 정리 가능

---

# 핵심 정리

1. 예외는 프로그램 실행 중 발생하는 오류 상황이다.
2. 예외를 사용하면 정상 흐름과 오류 흐름을 분리할 수 있다.
3. 체크 예외는 반드시 처리해야 한다.
4. 언체크 예외는 RuntimeException 계열이다.
5. 실무에서는 언체크 예외를 주로 사용한다.
6. 예외는 처리하지 못하면 상위로 전파된다.
7. finally는 항상 실행된다.
8. 예외 계층을 활용하면 공통 처리가 가능하다.
9. 사용자에게는 간단한 메시지를 제공한다.
10. 개발자에게는 상세 로그를 남긴다.
11. try-with-resources는 리소스 누수를 방지하는 가장 좋은 방법이다.
