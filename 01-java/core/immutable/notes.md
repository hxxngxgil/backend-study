# Immutable Object (불변 객체)

## 불변 객체란
불변 객체(Immutable Object)는 객체 생성 이후 내부 상태(값)를 변경할 수 없는 객체이다.

한 번 생성되면 객체의 데이터는 절대 변경되지 않는다.

---

## 기본형과 참조형의 차이

### 기본형
- 값을 직접 저장한다.
- 변수 복사 시 값 자체를 복사한다.
- 서로 영향을 주지 않는다.

예시

int a = 10;
int b = a;

b = 20;

→ a는 변경되지 않는다.

---

### 참조형
- 참조값(주소)을 저장한다.
- 변수 복사 시 참조값을 복사한다.
- 같은 객체를 공유할 수 있다.

예시

Student s1 = new Student();
Student s2 = s1;

→ 같은 객체를 참조한다.

---

## 공유 참조 (Shared Reference)

참조형은 하나의 객체를 여러 변수가 함께 사용할 수 있다.

예시

Address a1 = new Address("Seoul");
Address a2 = a1;

→ a1, a2는 같은 객체를 참조한다.

---

## 사이드 이펙트 (Side Effect)

공유된 객체의 값을 변경하면  
다른 참조 변수에도 영향을 준다.

예시

a2.setCity("Busan");

→ a1의 값도 함께 변경됨

이런 예상하지 못한 변경을 사이드 이펙트라고 한다.

---

## 불변 객체가 필요한 이유

공유 참조로 인한 사이드 이펙트를 방지하기 위해 사용한다.

불변 객체는 값을 변경할 수 없기 때문에  
안전하게 객체를 공유할 수 있다.

---

## 불변 객체 만들기

불변 객체를 만들기 위한 일반적인 방법

1. 필드를 private final로 선언
2. 값을 변경하는 setter 제거
3. 값을 변경할 경우 새로운 객체 생성

---

## 불변 객체 예시

class Address {
    private final String city;

    public Address(String city) {
        this.city = city;
    }

    public String getCity() {
        return city;
    }
}

---

## 불변 객체 값 변경

불변 객체는 기존 값을 수정하지 않는다.

값 변경이 필요하면 새로운 객체를 생성한다.

예시

Address a1 = new Address("Seoul");
Address a2 = new Address("Busan");

→ 기존 객체 유지
→ 새로운 객체 생성

---

## 불변 객체 장점

- 사이드 이펙트 방지
- 안정성 증가
- 객체 공유 안전
- 유지보수 용이

---

## 핵심 정리

1. 기본형은 값을 복사한다.
2. 참조형은 참조값을 복사한다.
3. 참조형은 객체 공유가 가능하다.
4. 공유 객체 변경 시 사이드 이펙트가 발생할 수 있다.
5. 불변 객체는 내부 값을 변경할 수 없다.
6. 값 변경이 필요하면 새로운 객체를 생성한다.
