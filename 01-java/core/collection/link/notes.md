# LinkedList

## 연결 리스트(LinkedList)

LinkedList는 노드(Node)를 연결하여 데이터를 저장하는 자료구조이다.

각 노드는

- 데이터(Data)
- 다음 노드의 주소(Reference)

를 가지고 있다.

예시

A → B → C → D

---

## 노드(Node)

노드는 LinkedList를 구성하는 가장 작은 단위이다.

하나의 노드는

- 데이터
- 다음 노드를 가리키는 참조값

으로 구성된다.

예시

[Data | Next]

---

## 연결 리스트의 특징

- 순서를 유지한다.
- 중복을 허용한다.
- 크기가 동적으로 변경된다.
- 노드들이 메모리에 연속적으로 저장되지 않는다.

---

## 직접 구현하는 LinkedList

직접 구현하면서 다음 기능을 만들 수 있다.

- 데이터 추가(add)
- 데이터 조회(get)
- 데이터 수정(set)
- 데이터 삭제(remove)
- 크기(size)

---

## 데이터 추가

앞에 추가

새 노드를 생성하여 첫 번째 노드 앞에 연결한다.

중간 추가

이전 노드를 찾아 연결을 변경한다.

마지막 추가

마지막 노드를 찾아 새로운 노드를 연결한다.

---

## 데이터 삭제

삭제할 노드의 이전 노드를 찾아

다음 노드를 연결하면 된다.

노드 자체를 이동하지 않는다.

---

## 제네릭 적용

LinkedList도 제네릭을 사용하여

타입 안정성을 제공한다.

예시

LinkedList<String>

LinkedList<Integer>

---

# LinkedList 시간 복잡도(Big-O)

## 데이터 추가

### 앞 추가

O(1)

---

### 마지막 추가

O(n)

(마지막 노드를 찾는 경우)

※ tail을 관리하면 O(1)

---

### 중간 추가

O(n)

(추가 위치를 먼저 찾아야 함)

---

## 데이터 삭제

### 앞 삭제

O(1)

---

### 마지막 삭제

O(n)

(이전 노드를 찾아야 함)

---

### 중간 삭제

O(n)

(삭제할 위치를 찾아야 함)

---

## 인덱스 조회

O(n)

처음부터 순차적으로 이동해야 한다.

---

## 데이터 검색

O(n)

처음부터 순차 탐색한다.

---

# ArrayList vs LinkedList

| 작업 | ArrayList | LinkedList |
|------|-----------|------------|
| 마지막 추가 | O(1) | O(n) *(tail 사용 시 O(1))* |
| 앞 추가 | O(n) | O(1) |
| 중간 추가 | O(n) | O(n) |
| 마지막 삭제 | O(1) | O(n) |
| 앞 삭제 | O(n) | O(1) |
| 중간 삭제 | O(n) | O(n) |
| 인덱스 조회 | O(1) | O(n) |
| 데이터 검색 | O(n) | O(n) |

---

# ArrayList와 LinkedList 선택 기준

## ArrayList

장점

- 조회가 매우 빠르다.
- 메모리 효율이 좋다.
- 대부분의 상황에서 성능이 우수하다.

추천

조회가 많은 경우

---

## LinkedList

장점

- 앞쪽 삽입/삭제가 빠르다.
- 노드를 이동하지 않고 연결만 변경한다.

추천

앞쪽 삽입/삭제가 매우 많은 경우

---

# 실무에서는?

실무에서는 대부분

ArrayList를 사용한다.

LinkedList는

앞이나 중간에서 삽입/삭제가 매우 빈번한
특수한 경우에만 사용하는 편이다.

---

# 핵심 정리

1. LinkedList는 노드를 연결하여 데이터를 저장한다.
2. 각 노드는 데이터와 다음 노드의 참조값을 가진다.
3. LinkedList는 크기가 동적으로 변경된다.
4. 앞쪽 삽입/삭제는 O(1)이다.
5. 인덱스 조회는 O(n)이다.
6. ArrayList는 조회에 강하다.
7. LinkedList는 앞쪽 삽입/삭제에 강하다.
8. 실무에서는 대부분 ArrayList를 사용한다.
