# List

## List 인터페이스

List는 순서가 있는 데이터를 저장하는 컬렉션 인터페이스이다.

특징

- 순서를 유지한다.
- 중복을 허용한다.
- 구현체를 교체하기 쉽다.

대표 구현체

- ArrayList
- LinkedList

---

# 리스트 추상화

클라이언트는 구현체(ArrayList, LinkedList)가 아니라

List 인터페이스에 의존하도록 설계하는 것이 좋다.

예시

List<String> list = new ArrayList<>();

필요하면

List<String> list = new LinkedList<>();

로 쉽게 변경할 수 있다.

---

# 인터페이스 도입

인터페이스를 사용하면

구현체를 변경하더라도

클라이언트 코드를 수정하지 않아도 된다.

장점

- 유지보수 용이
- 확장성 증가
- 결합도 감소

---

# 의존관계 주입(DI)

객체가 사용할 구현체를

외부에서 전달받는 방식이다.

예시

List<String> list = new ArrayList<>();

↓

List<String> list = new LinkedList<>();

클라이언트 코드를 수정하지 않고

구현체만 변경할 수 있다.

---

# 컴파일 타임 의존관계

소스 코드에서 의존하는 대상

예시

List

컴파일 시점에는

인터페이스에만 의존한다.

---

# 런타임 의존관계

실제 실행 시 사용하는 객체

예시

ArrayList

또는

LinkedList

실행 시점에 구현체가 결정된다.

---

# 전략 패턴(Strategy Pattern)

여러 알고리즘을 캡슐화하고

필요에 따라 쉽게 교체할 수 있도록 하는 디자인 패턴이다.

클라이언트 코드를 변경하지 않고

동작 방식을 변경할 수 있다.

예시

List<String> list = new ArrayList<>();

↓

List<String> list = new LinkedList<>();

전략(구현체)만 변경된다.

※ 디자인 패턴 중 가장 중요한 패턴 중 하나이다.

---

# 직접 구현한 리스트 성능 비교

| 작업 | ArrayList | LinkedList |
|------|-----------|------------|
| 마지막 추가 | O(1) | O(n) *(tail 사용 시 O(1))* |
| 앞 추가 | O(n) | O(1) |
| 중간 추가 | O(n) | O(n) |
| 마지막 삭제 | O(1) | O(n) |
| 앞 삭제 | O(n) | O(1) |
| 중간 삭제 | O(n) | O(n) |
| 인덱스 조회 | O(1) | O(n) |
| 데이터 검색 | O(n) | O(n) |

# 자바 List

자바에서는 List 인터페이스를 제공한다.

대표 구현체

- ArrayList
- LinkedList

필요에 따라 구현체를 변경할 수 있다.

---

# 자바 List 성능 비교

이론적으로는

LinkedList가

삽입/삭제 성능이 더 좋다.

하지만 실제로는

ArrayList가 더 좋은 성능을 보이는 경우가 대부분이다.

---

## ArrayList가 실제로 더 빠른 이유

- CPU 캐시(Cache) 효율이 좋다.
- 메모리가 연속적으로 저장된다.
- 객체를 따라 이동하는 비용이 없다.
- 실제 삽입/삭제보다 조회가 훨씬 많이 발생한다.

따라서

실무에서는 대부분 ArrayList를 사용한다.

---

# 실무에서의 선택

특별한 이유가 없다면

List 구현체는

ArrayList를 사용하는 것이 일반적이다.

LinkedList는

앞쪽 삽입/삭제가 매우 빈번한 특수한 상황에서만 고려한다.

---

# 핵심 정리

1. List는 순서를 유지하고 중복을 허용하는 컬렉션 인터페이스이다.
2. 대표 구현체는 ArrayList와 LinkedList이다.
3. 인터페이스를 사용하면 구현체를 쉽게 변경할 수 있다.
4. DI(의존관계 주입)를 사용하면 구현체를 외부에서 결정할 수 있다.
5. 컴파일 시에는 인터페이스(List)에 의존한다.
6. 실행 시에는 실제 구현체(ArrayList, LinkedList)가 결정된다.
7. 전략 패턴은 알고리즘을 쉽게 교체할 수 있도록 하는 디자인 패턴이다.
8. 이론적으로는 LinkedList가 삽입/삭제에 유리하다.
9. 실제 성능은 CPU 캐시 등의 이유로 ArrayList가 더 좋은 경우가 많다.
10. 실무에서는 대부분 ArrayList를 사용한다.
