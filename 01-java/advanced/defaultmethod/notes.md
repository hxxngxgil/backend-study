# Default Method

## 디폴트 메서드란

디폴트 메서드는 인터페이스에 구현 코드를 가질 수 있게 해주는 기능이다.

기존 인터페이스는 추상 메서드만 가질 수 있었다.

하지만 자바 8부터는 인터페이스에 default 키워드를 사용해서  
기본 구현을 가진 메서드를 만들 수 있다.

예시

interface MyInterface {
    default void hello() {
        System.out.println("hello");
    }
}

---

# 디폴트 메서드가 등장한 이유

## 기존 인터페이스의 문제점

인터페이스는 여러 클래스가 공통으로 지켜야 하는 규칙을 정의한다.

예시

interface MyInterface {
    void method1();
}

이 인터페이스를 여러 클래스가 구현하고 있다고 가정한다.

class A implements MyInterface {
    @Override
    public void method1() {
        System.out.println("A.method1");
    }
}

class B implements MyInterface {
    @Override
    public void method1() {
        System.out.println("B.method1");
    }
}

---

## 인터페이스에 메서드를 추가하면 생기는 문제

기존 인터페이스에 새로운 메서드를 추가하면  
그 인터페이스를 구현한 모든 클래스에서 오류가 발생한다.

예시

interface MyInterface {
    void method1();
    void method2();
}

문제점

- A 클래스도 method2()를 구현해야 한다.
- B 클래스도 method2()를 구현해야 한다.
- 이미 많은 구현 클래스가 있다면 전부 수정해야 한다.
- 기존 코드와의 호환성이 깨진다.

---

## 하위 호환성 문제

이미 배포된 인터페이스에 새로운 기능을 추가하면  
기존 구현 클래스들이 모두 영향을 받는다.

이런 문제를 하위 호환성 문제라고 볼 수 있다.

디폴트 메서드는 이런 문제를 해결하기 위해 등장했다.

---

## 디폴트 메서드의 등장 이유

디폴트 메서드를 사용하면 인터페이스에 새로운 메서드를 추가하면서도  
기존 구현 클래스가 깨지지 않게 만들 수 있다.

예시

interface MyInterface {
    void method1();

    default void method2() {
        System.out.println("default method2");
    }
}

기존 구현 클래스는 method2()를 직접 구현하지 않아도 된다.

필요한 클래스만 method2()를 오버라이딩하면 된다.

---

# 디폴트 메서드 소개

## 기본 문법

디폴트 메서드는 인터페이스 안에서 default 키워드로 정의한다.

예시

interface MyInterface {
    default void hello() {
        System.out.println("hello");
    }
}

---

## 디폴트 메서드 사용

class MyClass implements MyInterface {
}

MyClass myClass = new MyClass();

myClass.hello();

결과

hello

MyClass가 hello()를 직접 구현하지 않아도  
인터페이스의 기본 구현이 실행된다.

---

## 디폴트 메서드 오버라이딩

구현 클래스에서 디폴트 메서드를 재정의할 수 있다.

예시

class MyClass implements MyInterface {

    @Override
    public void hello() {
        System.out.println("MyClass.hello");
    }
}

이 경우 인터페이스의 기본 구현이 아니라  
구현 클래스에서 재정의한 메서드가 실행된다.

---

## 디폴트 메서드 특징

- 인터페이스에 구현 코드를 작성할 수 있다.
- default 키워드를 사용한다.
- 구현 클래스에서 반드시 오버라이딩하지 않아도 된다.
- 필요하면 구현 클래스에서 오버라이딩할 수 있다.
- 기존 인터페이스에 새 기능을 추가할 때 하위 호환성을 유지할 수 있다.

---

# 디폴트 메서드와 추상 메서드

## 추상 메서드

추상 메서드는 구현 코드가 없다.

인터페이스를 구현하는 클래스가 반드시 구현해야 한다.

예시

interface MyInterface {
    void method();
}

---

## 디폴트 메서드

디폴트 메서드는 구현 코드가 있다.

구현 클래스가 반드시 구현하지 않아도 된다.

예시

interface MyInterface {
    default void method() {
        System.out.println("default method");
    }
}

---

## 추상 메서드와 디폴트 메서드 비교

| 구분 | 추상 메서드 | 디폴트 메서드 |
|------|-------------|---------------|
| 구현 코드 | 없음 | 있음 |
| 구현 클래스의 구현 의무 | 반드시 구현 | 선택적으로 오버라이딩 |
| 목적 | 반드시 지켜야 할 규칙 정의 | 기본 동작 제공 |
| 키워드 | 없음 | default |

---

# 디폴트 메서드가 필요한 대표 상황

## 기존 인터페이스에 기능 추가

이미 많은 클래스가 구현 중인 인터페이스에  
새로운 메서드를 추가해야 할 때 사용할 수 있다.

예시

interface Collection<E> {
    boolean add(E e);

    default Stream<E> stream() {
        // 기본 구현
    }
}

기존 구현체가 모두 깨지지 않게 하면서  
새로운 기능을 추가할 수 있다.

---

## 공통 기본 동작 제공

여러 구현 클래스에서 공통으로 사용할 수 있는 기본 동작을  
인터페이스에서 제공할 수 있다.

예시

interface Printer {
    void print(String message);

    default void printLine(String message) {
        print(message);
        print("\n");
    }
}

print()는 구현 클래스가 직접 구현하고,  
printLine()은 기본 동작으로 제공할 수 있다.

---

# 디폴트 메서드의 올바른 사용법

## 1. 하위 호환성을 위해 사용한다

디폴트 메서드는 기존 인터페이스에 새로운 기능을 추가할 때  
기존 구현 클래스를 깨뜨리지 않기 위한 목적으로 사용하는 것이 좋다.

좋은 사용 예시

- 기존 인터페이스에 편의 기능 추가
- 기존 구현체에 영향을 덜 주면서 기능 확장
- 여러 구현체가 공통으로 사용할 수 있는 기본 메서드 제공

---

## 2. 인터페이스의 본래 역할을 유지해야 한다

인터페이스는 기본적으로 규칙과 역할을 정의하는 곳이다.

디폴트 메서드가 있다고 해서  
인터페이스에 복잡한 구현 로직을 많이 넣는 것은 좋지 않다.

인터페이스에 너무 많은 구현 로직이 들어가면  
인터페이스의 역할이 흐려질 수 있다.

---

## 3. 공통으로 자연스러운 기본 동작일 때 사용한다

디폴트 메서드는 모든 구현체에 공통으로 적용해도  
어색하지 않은 기본 동작일 때 사용하는 것이 좋다.

예시

interface Named {
    String getName();

    default void printName() {
        System.out.println(getName());
    }
}

printName()은 getName()을 활용한 공통 편의 기능이므로  
디폴트 메서드로 제공할 수 있다.

---

## 4. 구현 클래스마다 동작이 달라야 한다면 추상 메서드가 낫다

구현 클래스마다 반드시 다르게 구현해야 하는 기능이라면  
디폴트 메서드보다 추상 메서드로 두는 것이 좋다.

좋지 않은 예시

interface Payment {
    default void pay() {
        System.out.println("결제 처리");
    }
}

결제 방식은 카드, 계좌이체, 간편결제마다 다를 수 있다.

이런 핵심 비즈니스 동작은  
기본 구현을 제공하기보다 각 구현 클래스에서 명확하게 구현하는 것이 좋다.

---

# 디폴트 메서드 사용 시 주의점

## 1. 복잡한 비즈니스 로직을 넣지 않는다

디폴트 메서드는 인터페이스에 구현을 넣을 수 있지만  
복잡한 비즈니스 로직을 넣는 용도로 사용하는 것은 좋지 않다.

이유

- 인터페이스의 책임이 커진다.
- 코드 흐름을 파악하기 어려워질 수 있다.
- 구현 클래스의 역할이 애매해질 수 있다.
- 유지보수가 어려워질 수 있다.

---

## 2. 상태를 가지는 로직에 적합하지 않다

인터페이스는 인스턴스 필드를 가질 수 없다.

따라서 상태를 관리해야 하는 복잡한 로직은  
디폴트 메서드에 적합하지 않다.

상태가 필요한 로직은 클래스에서 구현하는 것이 좋다.

---

## 3. 다중 구현 충돌을 주의해야 한다

자바 클래스는 여러 인터페이스를 구현할 수 있다.

만약 두 인터페이스가 같은 시그니처의 디폴트 메서드를 가지고 있다면  
구현 클래스에서 어떤 메서드를 사용할지 직접 오버라이딩해야 한다.

예시

interface A {
    default void hello() {
        System.out.println("A.hello");
    }
}

interface B {
    default void hello() {
        System.out.println("B.hello");
    }
}

class C implements A, B {

    @Override
    public void hello() {
        A.super.hello();
    }
}

---

## 4. 클래스가 우선한다

부모 클래스에 같은 메서드가 있고  
인터페이스에도 같은 디폴트 메서드가 있으면  
클래스의 메서드가 우선한다.

즉, 클래스가 인터페이스보다 우선순위가 높다.

---

# 디폴트 메서드 충돌 규칙

## 규칙 1. 클래스가 우선한다

부모 클래스의 메서드와 인터페이스의 디폴트 메서드가 충돌하면  
부모 클래스의 메서드가 우선한다.

---

## 규칙 2. 인터페이스끼리 충돌하면 직접 오버라이딩해야 한다

여러 인터페이스에 같은 디폴트 메서드가 있으면  
구현 클래스에서 반드시 재정의해야 한다.

---

## 규칙 3. 오버라이딩하면 구현 클래스의 메서드가 우선한다

구현 클래스에서 디폴트 메서드를 오버라이딩하면  
구현 클래스의 메서드가 실행된다.

---

# 디폴트 메서드와 다중 상속

자바는 클래스 다중 상속을 지원하지 않는다.

하지만 인터페이스는 여러 개 구현할 수 있다.

디폴트 메서드가 생기면서  
인터페이스에도 구현 코드가 들어갈 수 있게 되었지만,  
자바는 충돌 규칙을 통해 모호성을 해결한다.

중요한 점

디폴트 메서드는 클래스 다중 상속을 허용하기 위한 기능이 아니다.

기존 인터페이스에 기능을 추가하면서  
하위 호환성을 유지하기 위한 기능이다.

---

# 디폴트 메서드의 장점

## 하위 호환성 유지

기존 인터페이스에 새 메서드를 추가해도  
기존 구현 클래스가 바로 깨지지 않는다.

---

## 코드 중복 감소

여러 구현체에서 공통으로 사용할 수 있는 간단한 로직을  
인터페이스에서 기본 구현으로 제공할 수 있다.

---

## 확장성 향상

기존 구조를 크게 바꾸지 않고  
인터페이스에 새로운 기능을 추가할 수 있다.

---

## 편의 메서드 제공

추상 메서드를 조합해서  
자주 사용하는 편의 기능을 제공할 수 있다.

---

# 디폴트 메서드의 단점

## 인터페이스 역할이 흐려질 수 있다

인터페이스는 원래 규칙을 정의하는 역할이다.

디폴트 메서드에 구현 로직이 많아지면  
인터페이스가 클래스처럼 사용될 수 있다.

---

## 복잡한 로직에 부적합하다

상태 관리나 복잡한 비즈니스 로직은  
디폴트 메서드보다 클래스에서 처리하는 것이 좋다.

---

## 충돌 가능성이 있다

여러 인터페이스를 구현할 때  
같은 이름과 시그니처의 디폴트 메서드가 있으면 충돌이 발생할 수 있다.

---

# 디폴트 메서드 사용 기준

## 사용하기 좋은 경우

- 기존 인터페이스에 새 기능을 추가해야 할 때
- 기존 구현 클래스와의 호환성을 유지해야 할 때
- 여러 구현체에 공통으로 적용 가능한 간단한 기본 동작이 있을 때
- 추상 메서드를 활용한 편의 메서드를 제공할 때

---

## 피하는 것이 좋은 경우

- 복잡한 비즈니스 로직
- 구현 클래스마다 반드시 달라야 하는 핵심 동작
- 상태를 관리해야 하는 로직
- 인터페이스 책임을 지나치게 키우는 경우

---

# 핵심 정리

1. 디폴트 메서드는 인터페이스에 구현 코드를 작성할 수 있게 해주는 기능이다.
2. default 키워드를 사용해서 정의한다.
3. 디폴트 메서드는 자바 8부터 도입되었다.
4. 디폴트 메서드는 기존 인터페이스에 새 기능을 추가할 때 하위 호환성을 유지하기 위해 등장했다.
5. 추상 메서드는 구현 클래스가 반드시 구현해야 하지만, 디폴트 메서드는 선택적으로 오버라이딩할 수 있다.
6. 디폴트 메서드는 인터페이스의 기본 동작이나 편의 기능을 제공할 때 사용할 수 있다.
7. 복잡한 비즈니스 로직을 디폴트 메서드에 넣는 것은 권장하지 않는다.
8. 여러 인터페이스의 디폴트 메서드가 충돌하면 구현 클래스에서 직접 오버라이딩해야 한다.
9. 부모 클래스의 메서드와 인터페이스의 디폴트 메서드가 충돌하면 클래스의 메서드가 우선한다.
10. 디폴트 메서드는 클래스 다중 상속을 위한 기능이 아니라 인터페이스 확장과 하위 호환성을 위한 기능이다.
11. 디폴트 메서드는 모든 구현체에 자연스럽게 적용 가능한 간단한 기본 동작일 때 사용하는 것이 좋다.
