# Functional Programming

## 함수형 프로그래밍

이번 단원에서는 프로그래밍 패러다임의 종류와  
함수형 프로그래밍이 무엇인지,  
그리고 자바에서 함수형 프로그래밍을 어떻게 활용하는지 학습했다.

학습 흐름

1. 프로그래밍 패러다임
2. 함수형 프로그래밍이란?
3. 자바와 함수형 프로그래밍

---

# 프로그래밍 패러다임

## 프로그래밍 패러다임이란?

프로그래밍 패러다임은 프로그램을 작성하는 방식이나 관점이다.

즉, 문제를 어떤 방식으로 바라보고  
코드를 어떤 구조로 작성할 것인지에 대한 사고방식이다.

대표적인 프로그래밍 패러다임

- 절차지향 프로그래밍
- 객체지향 프로그래밍
- 함수형 프로그래밍

---

## 절차지향 프로그래밍

절차지향 프로그래밍은 프로그램을 순서대로 실행되는 절차 중심으로 작성하는 방식이다.

특징

- 실행 순서가 중요하다.
- 데이터를 처리하는 절차를 중심으로 작성한다.
- 함수나 프로시저를 사용해서 코드를 나눈다.

예시 흐름

1. 입력을 받는다.
2. 데이터를 처리한다.
3. 결과를 출력한다.

장점

- 실행 흐름을 이해하기 쉽다.
- 단순한 프로그램에 적합하다.

단점

- 프로그램이 커질수록 데이터와 로직 관리가 어려워질 수 있다.

---

## 객체지향 프로그래밍

객체지향 프로그래밍은 프로그램을 객체들의 협력으로 바라보는 방식이다.

객체는 데이터와 기능을 함께 가진다.

특징

- 객체 중심
- 캡슐화
- 상속
- 다형성
- 역할과 책임 분리

예시

회원 객체

- 데이터: 이름, 나이
- 기능: 회원 정보 변경, 회원 검증

장점

- 큰 프로그램을 역할별로 나누기 좋다.
- 유지보수와 확장에 유리하다.

---

## 함수형 프로그래밍

함수형 프로그래밍은 함수를 중심으로 프로그램을 작성하는 방식이다.

데이터를 직접 변경하기보다  
입력값을 받아 새로운 결과를 만들어내는 방식에 가깝다.

핵심 개념

- 순수 함수
- 불변성
- 부수 효과 최소화
- 선언형 스타일
- 함수를 값처럼 사용

---

# 함수형 프로그래밍이란?

## 함수형 프로그래밍의 기본 생각

함수형 프로그래밍은 프로그램을  
값의 변경 과정이 아니라 값의 변환 과정으로 바라본다.

즉, 데이터를 직접 바꾸기보다는  
기존 데이터를 바탕으로 새로운 결과를 만든다.

예시

원본 데이터

1, 2, 3, 4, 5

처리

짝수만 고른다.

각 값을 2배로 바꾼다.

결과

4, 8

---

## 명령형 스타일

명령형 스타일은 어떻게 처리할지를 직접 작성하는 방식이다.

예시

List<Integer> result = new ArrayList<>();

for (Integer number : numbers) {
    if (number % 2 == 0) {
        result.add(number * 2);
    }
}

특징

- 반복문을 직접 작성한다.
- 조건문을 직접 작성한다.
- 결과 리스트에 값을 직접 추가한다.
- 처리 방법이 코드에 자세히 드러난다.

---

## 선언형 스타일

선언형 스타일은 무엇을 할지를 중심으로 작성하는 방식이다.

예시

List<Integer> result = numbers.stream()
        .filter(number -> number % 2 == 0)
        .map(number -> number * 2)
        .toList();

특징

- 짝수만 고른다.
- 각 값을 2배로 바꾼다.
- 리스트로 만든다.

반복을 어떻게 수행하는지는 Stream API가 처리한다.

개발자는 데이터 처리 의도에 집중할 수 있다.

---

# 순수 함수

## 순수 함수란?

순수 함수는 같은 입력이 들어오면 항상 같은 결과를 반환하는 함수이다.

그리고 함수 외부의 상태를 변경하지 않는다.

---

## 순수 함수 예시

static int add(int a, int b) {
    return a + b;
}

특징

- add(1, 2)는 항상 3을 반환한다.
- 외부 변수나 객체 상태를 변경하지 않는다.
- 결과를 예측하기 쉽다.

---

## 순수 함수가 아닌 예시

static int total = 0;

static int addTotal(int value) {
    total += value;
    return total;
}

문제점

- 외부 변수 total을 변경한다.
- 같은 값을 넣어도 이전 상태에 따라 결과가 달라질 수 있다.
- 결과 예측이 어려워진다.

---

## 순수 함수의 장점

- 테스트하기 쉽다.
- 결과를 예측하기 쉽다.
- 디버깅이 쉬워진다.
- 병렬 처리에 유리하다.
- 코드 안정성이 높아진다.

---

# 불변성

## 불변성이란?

불변성은 한 번 만들어진 값을 변경하지 않는 성질이다.

함수형 프로그래밍에서는 기존 값을 직접 수정하기보다  
새로운 값을 만들어 반환하는 방식을 선호한다.

---

## 가변 객체 방식

class Member {
    private String name;

    public void changeName(String name) {
        this.name = name;
    }
}

이 방식은 기존 객체의 상태를 직접 변경한다.

---

## 불변 객체 방식

class Member {
    private final String name;

    public Member(String name) {
        this.name = name;
    }

    public Member changeName(String newName) {
        return new Member(newName);
    }
}

이 방식은 기존 객체를 변경하지 않고  
새로운 객체를 반환한다.

---

## 불변성이 중요한 이유

가변 상태가 많아지면  
어디서 값이 변경되었는지 추적하기 어려워진다.

특히 여러 스레드가 동시에 같은 데이터를 다루면  
상태 변경 때문에 문제가 발생할 수 있다.

불변성을 지키면 데이터가 중간에 바뀌지 않기 때문에  
코드의 안정성과 예측 가능성이 높아진다.

---

# 부수 효과 최소화

## 부수 효과란?

부수 효과는 함수가 자신의 결과 반환 외에  
외부 상태를 변경하거나 외부에 영향을 주는 것을 말한다.

예시

- 전역 변수 변경
- 객체 필드 변경
- 파일 쓰기
- DB 저장
- 콘솔 출력
- 네트워크 호출

---

## 부수 효과가 많은 코드의 문제점

- 결과를 예측하기 어렵다.
- 테스트하기 어렵다.
- 디버깅이 어렵다.
- 병렬 처리 시 문제가 생기기 쉽다.
- 코드의 실행 순서에 민감해진다.

---

## 부수 효과를 줄이는 방법

- 외부 상태 변경을 줄인다.
- 가능하면 새로운 값을 반환한다.
- 데이터를 직접 변경하지 않는다.
- 순수 함수에 가깝게 작성한다.
- 부수 효과가 필요한 코드는 명확한 위치에 모은다.

---

# 함수형 프로그래밍의 특징

## 1. 함수를 값처럼 다룬다

함수형 프로그래밍에서는 함수를 변수에 대입하거나  
메서드의 인자로 전달하거나  
메서드의 반환값으로 사용할 수 있다.

자바에서는 람다와 함수형 인터페이스를 사용해서  
함수를 값처럼 다룰 수 있다.

예시

Function<Integer, Integer> function = value -> value * 2;

---

## 2. 고차 함수를 사용한다

고차 함수는 함수를 인자로 받거나  
함수를 반환하는 함수이다.

예시

static int calculate(int value, Function<Integer, Integer> function) {
    return function.apply(value);
}

사용

calculate(10, value -> value * 2);

---

## 3. 선언형 스타일에 가깝다

함수형 프로그래밍은 어떻게 처리할지보다  
무엇을 할지에 집중한다.

예시

numbers.stream()
        .filter(number -> number % 2 == 0)
        .map(number -> number * 2)
        .toList();

이 코드는 다음 의도를 명확하게 표현한다.

1. 짝수만 고른다.
2. 2배로 변환한다.
3. 리스트로 만든다.

---

## 4. 상태 변경을 줄인다

함수형 프로그래밍은 가능한 한 상태 변경을 줄인다.

상태 변경이 줄어들면  
코드의 흐름을 예측하기 쉬워지고  
동시성 문제도 줄일 수 있다.

---

# 자바와 함수형 프로그래밍

## 자바는 순수 함수형 언어는 아니다

자바는 기본적으로 객체지향 언어이다.

하지만 자바 8부터 람다, 함수형 인터페이스, Stream API, Optional, 디폴트 메서드 등이 추가되면서  
함수형 프로그래밍 스타일을 지원하게 되었다.

---

## 자바에서 함수형 프로그래밍을 지원하는 기능

대표 기능

- 람다
- 함수형 인터페이스
- 메서드 참조
- Stream API
- Optional
- 디폴트 메서드

---

## 람다

람다는 동작을 간결하게 표현하는 문법이다.

예시

value -> value * 2

람다를 사용하면 메서드에 동작을 전달할 수 있다.

예시

numbers.stream()
        .map(value -> value * 2)
        .toList();

---

## 함수형 인터페이스

함수형 인터페이스는 추상 메서드가 하나만 있는 인터페이스이다.

자바에서 람다는 함수형 인터페이스를 기반으로 동작한다.

대표 함수형 인터페이스

- Function
- Predicate
- Consumer
- Supplier
- UnaryOperator
- BinaryOperator

---

## 메서드 참조

메서드 참조는 이미 존재하는 메서드를 람다 대신 참조하는 문법이다.

예시

람다

value -> Integer.parseInt(value)

메서드 참조

Integer::parseInt

메서드 참조를 사용하면 코드가 더 간결해질 수 있다.

---

## Stream API

Stream API는 컬렉션 데이터를 함수형 스타일로 처리할 수 있게 해준다.

예시

List<Integer> result = numbers.stream()
        .filter(number -> number % 2 == 0)
        .map(number -> number * 2)
        .toList();

Stream API는 함수형 프로그래밍의 대표적인 활용 예시이다.

---

## Optional

Optional은 값이 있을 수도 있고 없을 수도 있음을 표현하는 객체이다.

Optional을 사용하면 null을 직접 다루는 코드를 줄일 수 있다.

예시

Optional<Member> member = findMember();

String name = member
        .map(value -> value.getName())
        .orElse("이름 없음");

---

# 함수형 프로그래밍의 장점

## 병렬 처리에 유리하다

함수형 프로그래밍은 순수 함수와 불변성을 중요하게 생각한다.

외부 상태를 변경하지 않고  
입력값을 바탕으로 결과를 만들면  
여러 작업을 동시에 실행해도 충돌 가능성이 줄어든다.

그래서 병렬 처리에 유리하다.

---

## 동시성 프로그래밍에 유리하다

동시성 문제는 여러 스레드가 같은 상태를 동시에 변경할 때 자주 발생한다.

함수형 프로그래밍은 상태 변경을 줄이고  
불변 데이터를 선호하기 때문에  
공유 가변 상태로 인한 문제를 줄일 수 있다.

---

## 코드 가독성이 좋아진다

함수형 스타일은 데이터 처리 의도를 명확하게 표현한다.

예시

filter

- 조건에 맞는 값만 남긴다.

map

- 값을 변환한다.

reduce

- 여러 값을 하나로 누적한다.

이름만 봐도 처리 의도를 파악하기 쉽다.

---

## 유지보수성이 좋아진다

순수 함수는 입력과 출력이 명확하다.

부수 효과가 적으면  
코드를 수정했을 때 다른 부분에 영향을 줄 가능성이 줄어든다.

또한 작은 함수들을 조합해서 사용하면  
기능을 변경하거나 확장하기 쉬워진다.

---

# 함수형 프로그래밍 사용 시 주의점

## 무조건 함수형 스타일이 좋은 것은 아니다

함수형 프로그래밍은 강력하지만  
모든 상황에 항상 적합한 것은 아니다.

너무 복잡한 로직을 스트림이나 람다 체인으로 억지로 작성하면  
오히려 가독성이 떨어질 수 있다.

---

## 복잡한 비즈니스 로직은 분리한다

람다나 스트림 내부에 조건문과 복잡한 계산이 많이 들어가면  
코드가 읽기 어려워진다.

이 경우 별도 메서드로 분리하는 것이 좋다.

예시

members.stream()
        .filter(member -> isValidMember(member))
        .map(member -> convertToDto(member))
        .toList();

이렇게 메서드 이름으로 의도를 드러내면 가독성이 좋아진다.

---

## 부수 효과가 필요한 경우도 있다

실제 애플리케이션에서는 DB 저장, 파일 쓰기, 로그 출력, 네트워크 호출 같은 부수 효과가 필요하다.

중요한 것은 부수 효과를 완전히 없애는 것이 아니라  
부수 효과가 발생하는 위치를 명확하게 관리하는 것이다.

---

# 함수형 프로그래밍을 사용하기 좋은 경우

- 컬렉션 데이터를 필터링할 때
- 데이터를 다른 형태로 변환할 때
- 합계, 평균, 개수 같은 집계를 할 때
- 조건, 변환, 소비 로직을 전달할 때
- 병렬 처리를 고려할 때
- 반복되는 로직에서 변하는 부분만 전달하고 싶을 때

---

# 함수형 프로그래밍보다 명령형 코드가 나을 수 있는 경우

- 로직의 흐름이 복잡할 때
- 중간 상태 변경이 많을 때
- 예외 처리나 분기 처리가 복잡할 때
- 디버깅이 중요한 복잡한 절차 코드일 때
- 스트림 체인이 너무 길어져서 읽기 어려울 때

---

# 객체지향과 함수형 프로그래밍

객체지향과 함수형 프로그래밍은 서로 반대라기보다  
상황에 따라 함께 사용할 수 있는 방식이다.

자바에서는 객체지향 구조를 기본으로 가져가면서  
컬렉션 처리나 동작 전달에는 함수형 스타일을 활용할 수 있다.

예시

- 도메인 구조는 객체지향으로 설계한다.
- 리스트 조회, 필터링, 변환은 Stream API를 사용한다.
- 변하는 조건이나 전략은 람다로 전달한다.
- 값이 없을 수 있는 결과는 Optional로 표현한다.

# 핵심 정리

1. 프로그래밍 패러다임은 프로그램을 작성하는 방식이나 관점이다.
2. 대표적인 패러다임에는 절차지향, 객체지향, 함수형 프로그래밍이 있다.
3. 함수형 프로그래밍은 함수를 중심으로 프로그램을 작성하는 방식이다.
4. 함수형 프로그래밍은 값의 변경보다 값의 변환에 집중한다.
5. 순수 함수는 같은 입력에 항상 같은 결과를 반환하고 외부 상태를 변경하지 않는다.
6. 불변성은 기존 값을 변경하지 않고 새로운 값을 만들어내는 방식이다.
7. 부수 효과는 함수가 외부 상태를 변경하거나 외부에 영향을 주는 것이다.
8. 함수형 프로그래밍은 부수 효과를 최소화하려고 한다.
9. 함수형 프로그래밍은 선언형 스타일에 가깝다.
10. 선언형 스타일은 어떻게 처리할지보다 무엇을 할지에 집중한다.
11. 자바는 순수 함수형 언어는 아니지만 함수형 프로그래밍 스타일을 지원한다.
12. 자바에서는 람다, 함수형 인터페이스, 메서드 참조, Stream API, Optional 등을 통해 함수형 스타일을 사용할 수 있다.
13. 함수형 프로그래밍은 상태 변경을 줄이기 때문에 병렬 처리와 동시성 프로그래밍에 유리하다.
14. 함수형 스타일은 데이터 처리 의도를 명확하게 표현해서 코드 가독성을 높일 수 있다.
15. 순수 함수와 부수 효과 최소화는 유지보수성을 높이는 데 도움이 된다.
16. 하지만 모든 코드를 함수형 스타일로 억지로 작성하는 것은 좋지 않다.
17. 복잡한 비즈니스 로직은 별도 메서드나 객체로 분리하는 것이 좋다.
18. 자바에서는 객체지향을 기본으로 하면서 필요한 부분에 함수형 스타일을 함께 활용하는 것이 현실적이다.
