# Character Encoding (문자 인코딩)

## 컴퓨터와 데이터

컴퓨터는 모든 데이터를 숫자로 저장한다.

문자도 컴퓨터 입장에서는 그대로 이해할 수 없기 때문에  
문자를 숫자로 변환해서 저장해야 한다.

---

## 컴퓨터와 문자 인코딩

문자를 컴퓨터에 저장하거나 다시 불러오려면  
반드시 문자 집합(Character Set)이 필요하다.

문자 집합은 문자와 숫자를 매핑하는 규칙이다.

예시

A → 65

컴퓨터는 문자 A를 직접 저장하는 것이 아니라  
A에 해당하는 숫자 값을 저장한다.

---

## 문자 집합(Character Set)

문자 집합은 사용할 수 있는 문자들의 모음과  
각 문자에 대응되는 숫자 규칙이다.

대표 문자 집합

- ASCII
- ISO-8859-1
- EUC-KR
- MS949
- UTF-16
- UTF-8

---

## 문자 인코딩

문자 인코딩은 문자를 컴퓨터가 저장할 수 있는 바이트 형태로 변환하는 방식이다.

문자 → 바이트

반대로 바이트를 문자로 다시 읽는 과정은 디코딩이라고 한다.

바이트 → 문자

---

## 인코딩과 디코딩

### 인코딩

문자를 바이트로 변환한다.

예시

문자열 "ABC"  
→ 바이트 데이터

---

### 디코딩

바이트 데이터를 문자로 변환한다.

예시

바이트 데이터  
→ 문자열 "ABC"

---

## 문자 집합 조회

자바에서는 사용 가능한 문자 집합을 조회할 수 있다.

예시

Charset.availableCharsets();

기본 문자 집합도 확인할 수 있다.

예시

Charset.defaultCharset();

---

## 자주 사용하는 Charset

자바에서는 StandardCharsets를 사용하면  
문자 집합 이름을 문자열로 직접 입력하지 않아도 된다.

예시

StandardCharsets.UTF_8  
StandardCharsets.UTF_16  
StandardCharsets.ISO_8859_1  
StandardCharsets.US_ASCII

---

## 문자 인코딩 사용 방법

문자열을 바이트 배열로 변환할 때 getBytes()를 사용한다.

예시

String text = "안녕하세요";
byte[] bytes = text.getBytes(StandardCharsets.UTF_8);

→ 문자열을 UTF-8 기준으로 바이트 배열로 변환한다.

---

## 문자 디코딩 사용 방법

바이트 배열을 다시 문자열로 변환할 때 new String()을 사용한다.

예시

String result = new String(bytes, StandardCharsets.UTF_8);

→ UTF-8 기준으로 바이트 배열을 문자열로 변환한다.

---

## 인코딩과 디코딩은 같은 문자 집합을 사용해야 한다

문자를 저장할 때 사용한 문자 집합과  
다시 읽을 때 사용하는 문자 집합이 다르면 문자가 깨질 수 있다.

예시

String text = "안녕하세요";

byte[] bytes = text.getBytes(StandardCharsets.UTF_8);

String result = new String(bytes, StandardCharsets.UTF_8);

→ 정상 출력

하지만

String result = new String(bytes, Charset.forName("EUC-KR"));

→ 문자가 깨질 수 있음

---

## ASCII

가장 기본적인 문자 집합이다.

특징

- 영어 알파벳, 숫자, 특수문자 표현
- 7비트 사용
- 다른 많은 문자 집합과 호환됨

단점

- 한글 표현 불가능

---

## ISO-8859-1

서유럽 문자 표현을 위한 문자 집합이다.

특징

- ASCII와 호환
- 1바이트 사용

단점

- 한글 표현 불가능

---

## EUC-KR

한글 표현을 위해 사용된 문자 집합이다.

특징

- ASCII와 호환
- 한글 표현 가능

단점

- 모든 한글 문자를 완벽하게 표현하지 못함
- 국제적인 호환성이 떨어짐

---

## MS949

EUC-KR을 확장한 문자 집합이다.

특징

- ASCII와 호환
- EUC-KR보다 더 많은 한글 표현 가능
- Windows 환경에서 많이 사용됨

단점

- 국제 표준으로 보기 어려움
- 다른 환경과 호환 문제가 발생할 수 있음

---

## UTF-16

유니코드 문자를 표현하는 인코딩 방식이다.

특징

- 다양한 언어 표현 가능
- 자바 내부 문자열 처리와 관련 있음

단점

- ASCII와 호환되지 않음
- 영어 위주의 데이터에서는 저장 공간 낭비가 발생할 수 있음

---

## UTF-8

현대에서 사실상 표준으로 사용되는 문자 인코딩 방식이다.

특징

- 유니코드 기반
- ASCII와 호환
- 영어는 1바이트로 저장
- 한글은 보통 3바이트로 저장
- 저장 공간과 네트워크 전송에 효율적

---

## UTF-8이 사실상 표준인 이유

UTF-8은 현대 웹과 서버 환경에서 가장 많이 사용된다.

주요 이유

1. ASCII와 호환된다.
2. 영어는 1바이트로 저장되어 공간 효율이 좋다.
3. 다양한 언어를 표현할 수 있다.
4. 네트워크 전송에 효율적이다.
5. 국제적인 호환성이 좋다.

---

## ASCII 호환 여부

대부분의 문자 집합은 ASCII와 호환된다.

예시

- ISO-8859-1
- EUC-KR
- MS949
- UTF-8

하지만 UTF-16은 ASCII와 호환되지 않는다.

---

## 문자 깨짐이 발생하는 이유

인코딩할 때 사용한 문자 집합과  
디코딩할 때 사용한 문자 집합이 다르면 문자가 깨질 수 있다.

예시

UTF-8로 저장한 데이터를  
EUC-KR로 읽으면 한글이 깨질 수 있다.

---

## 핵심 정리

1. 컴퓨터는 문자를 직접 이해하지 못하고 숫자로 저장한다.
2. 문자를 저장하거나 읽으려면 문자 집합이 필요하다.
3. 인코딩은 문자를 바이트로 변환하는 것이다.
4. 디코딩은 바이트를 문자로 변환하는 것이다.
5. 자바에서는 Charset.availableCharsets()로 문자 집합을 조회할 수 있다.
6. Charset.defaultCharset()으로 기본 문자 집합을 확인할 수 있다.
7. 문자열을 바이트로 바꿀 때는 getBytes(charset)를 사용한다.
8. 바이트를 문자열로 바꿀 때는 new String(bytes, charset)을 사용한다.
9. 인코딩과 디코딩 문자 집합이 다르면 문자가 깨질 수 있다.
10. UTF-16은 ASCII와 호환되지 않는다.
11. UTF-8은 ASCII와 호환된다.
12. UTF-8은 저장 공간 절약, 네트워크 효율성, 호환성 때문에 현대의 사실상 표준이다.
