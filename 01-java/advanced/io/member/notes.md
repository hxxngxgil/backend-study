# I/O 활용

## 회원 관리 예제

I/O 활용에서는 회원 데이터를 여러 방식으로 보관하는 예제를 학습했다.

회원 데이터를 저장하는 방식은 크게 다음과 같이 나눌 수 있다.

- 메모리에 보관
- 파일에 보관
- DataStream 사용
- ObjectStream 사용
- XML, JSON, Protobuf, Avro 같은 데이터 포맷 사용
- 데이터베이스 사용

---

# 회원 관리 예제 - 메모리

메모리에 데이터를 보관하는 방식이다.

예시

List<Member> members = new ArrayList<>();

특징

- 구현이 간단하다.
- 조회, 추가, 삭제가 빠르다.
- 프로그램이 종료되면 데이터가 모두 사라진다.

---

## 메모리 저장 방식의 장점

- 가장 단순하다.
- 파일 입출력이 필요 없다.
- 테스트나 간단한 예제에 적합하다.

---

## 메모리 저장 방식의 단점

- 프로그램을 종료하면 데이터가 사라진다.
- 데이터를 영구적으로 보관할 수 없다.

---

# 회원 관리 예제 - 파일에 보관

회원 데이터를 파일에 저장하면  
프로그램이 종료되어도 데이터를 유지할 수 있다.

예시

회원1
회원2
회원3

---

## 파일 저장 방식의 장점

- 프로그램 종료 후에도 데이터가 남는다.
- 간단한 데이터 저장에 사용할 수 있다.
- 별도의 데이터베이스 없이 데이터를 보관할 수 있다.

---

## 파일 저장 방식의 단점

- 데이터 형식을 직접 관리해야 한다.
- 데이터를 읽고 쓰는 코드가 복잡해질 수 있다.
- 데이터가 많아지면 관리가 어렵다.
- 검색, 수정, 삭제 기능을 직접 구현해야 한다.

---

# DataStream

DataStream은 자바의 기본 타입 데이터를 편리하게 읽고 쓸 수 있는 스트림이다.

대표 클래스

- DataInputStream
- DataOutputStream

---

## DataOutputStream

데이터를 타입에 맞게 파일에 저장할 수 있다.

예시

dataOutputStream.writeUTF(member.getId());
dataOutputStream.writeUTF(member.getName());
dataOutputStream.writeInt(member.getAge());

---

## DataInputStream

저장된 데이터를 타입에 맞게 다시 읽을 수 있다.

예시

String id = dataInputStream.readUTF();
String name = dataInputStream.readUTF();
int age = dataInputStream.readInt();

---

## DataStream의 특징

- 자바 기본 타입을 편리하게 저장할 수 있다.
- int, long, double, boolean, String 등을 타입에 맞게 저장할 수 있다.
- 저장한 순서와 읽는 순서가 반드시 같아야 한다.

---

## DataStream의 장점

- 문자열을 직접 파싱하지 않아도 된다.
- 타입에 맞게 데이터를 저장하고 읽을 수 있다.
- 파일 저장 방식보다 코드가 깔끔해질 수 있다.

---

## DataStream의 단점

- 저장 순서와 읽는 순서가 다르면 문제가 생긴다.
- 데이터 구조가 변경되면 기존 파일을 읽기 어려울 수 있다.
- 자바 중심의 방식이라 다른 언어나 시스템과의 호환성이 떨어질 수 있다.

---

# ObjectStream

ObjectStream은 객체 자체를 파일에 저장하고 다시 읽을 수 있는 스트림이다.

대표 클래스

- ObjectOutputStream
- ObjectInputStream

---

## ObjectOutputStream

객체를 파일에 저장할 수 있다.

예시

objectOutputStream.writeObject(member);

---

## ObjectInputStream

파일에 저장된 객체를 다시 읽을 수 있다.

예시

Member member = (Member) objectInputStream.readObject();

---

## Serializable

ObjectStream으로 객체를 저장하려면  
해당 객체는 Serializable 인터페이스를 구현해야 한다.

예시

class Member implements Serializable {
    private String id;
    private String name;
    private int age;
}

---

## ObjectStream의 장점

- 객체를 그대로 저장할 수 있다.
- 직접 데이터를 하나씩 분리해서 저장하지 않아도 된다.
- 코드가 간단해질 수 있다.

---

## ObjectStream의 단점

- 자바 전용 방식에 가깝다.
- 다른 언어나 시스템과의 호환성이 좋지 않다.
- 클래스 구조가 변경되면 역직렬화 문제가 발생할 수 있다.
- 장기 저장용 데이터 포맷으로는 적합하지 않을 수 있다.

---

# 직렬화와 역직렬화

## 직렬화

객체를 파일이나 네트워크로 보낼 수 있는 형태로 변환하는 것이다.

객체 → 바이트 데이터

---

## 역직렬화

저장된 바이트 데이터를 다시 객체로 복원하는 것이다.

바이트 데이터 → 객체

---

# XML

XML은 데이터를 태그 형태로 표현하는 데이터 포맷이다.

예시

<member>
    <id>id1</id>
    <name>memberA</name>
</member>

---

## XML 특징

- 태그 기반 구조
- 사람이 읽을 수 있다.
- 구조가 명확하다.
- 과거에 많이 사용되었다.

---

## XML 단점

- 데이터 표현이 길고 무겁다.
- 같은 데이터를 표현해도 JSON보다 용량이 커질 수 있다.
- 작성과 파싱이 번거로울 수 있다.

---

# JSON

JSON은 Key-Value 형태로 데이터를 표현하는 데이터 포맷이다.

예시

{
    "id": "id1",
    "name": "memberA",
    "age": 20
}

---

## JSON 특징

- 현재 가장 많이 사용되는 데이터 포맷
- 웹, 서버, API 통신에서 사실상 표준처럼 사용된다.
- 사람이 읽기 쉽다.
- 구조가 단순하다.
- 관리와 유지보수가 쉽다.

---

## JSON 장점

- 가볍다.
- 사람이 읽고 이해하기 쉽다.
- 다양한 언어와 시스템에서 지원한다.
- API 통신에 많이 사용된다.
- 유지보수하기 좋다.

---

## JSON 단점

- 바이너리 포맷보다 성능과 용량 면에서 불리할 수 있다.
- 매우 높은 성능 최적화가 필요한 환경에서는 다른 포맷을 고려할 수 있다.

---

# Protobuf

Protobuf는 Google에서 만든 바이너리 데이터 직렬화 포맷이다.

특징

- 바이너리 기반
- 크기가 작다.
- 속도가 빠르다.
- 스키마를 정의해서 사용한다.

---

## Protobuf 장점

- JSON보다 빠르고 용량이 작을 수 있다.
- 네트워크 전송 효율이 좋다.
- 성능 최적화가 중요한 환경에서 사용할 수 있다.

---

## Protobuf 단점

- 사람이 직접 읽기 어렵다.
- 스키마 관리가 필요하다.
- JSON보다 관리와 유지보수가 복잡할 수 있다.
- 일반적인 서비스에서는 사용할 일이 많지 않을 수 있다.

---

# Avro

Avro는 데이터 직렬화를 위한 바이너리 포맷이다.

특징

- 바이너리 기반
- 스키마 기반
- 대용량 데이터 처리 환경에서 사용될 수 있다.

---

## Avro 장점

- 대용량 데이터 처리에 적합하다.
- 바이너리 기반이라 효율적이다.
- 데이터 처리 시스템에서 사용될 수 있다.

---

## Avro 단점

- 사람이 직접 읽기 어렵다.
- 스키마 관리가 필요하다.
- 일반적인 웹 애플리케이션에서는 자주 사용하지 않는다.
- JSON보다 관리와 유지보수가 어렵다.

---

# 데이터베이스

데이터베이스는 데이터를 체계적으로 저장하고 관리하는 시스템이다.

회원 정보처럼 계속 유지되어야 하는 데이터는  
실무에서 대부분 데이터베이스에 저장한다.

---

## 데이터베이스 장점

- 데이터를 안전하게 저장할 수 있다.
- 검색, 수정, 삭제가 편리하다.
- 대량의 데이터를 관리하기 좋다.
- 트랜잭션을 지원한다.
- 여러 사용자가 동시에 접근할 수 있다.

---

## 데이터베이스 단점

- 별도의 설치와 관리가 필요하다.
- SQL이나 데이터베이스 사용법을 알아야 한다.
- 단순 파일 저장보다 구조가 복잡하다.

---

# 데이터 저장 방식 비교

| 방식 | 특징 | 장점 | 단점 |
|------|------|------|------|
| 메모리 | 프로그램 실행 중에만 저장 | 빠르고 단순함 | 종료 시 데이터 사라짐 |
| 파일 | 파일에 직접 저장 | 영구 보관 가능 | 검색, 수정, 삭제 관리 어려움 |
| DataStream | 타입 기반 저장 | 기본 타입 저장 편리 | 순서가 중요하고 호환성 낮음 |
| ObjectStream | 객체 자체 저장 | 코드가 간단함 | 자바 의존적이고 구조 변경에 약함 |
| XML | 태그 기반 데이터 | 구조 명확 | 무겁고 길다 |
| JSON | Key-Value 기반 데이터 | 읽기 쉽고 표준처럼 사용 | 바이너리보다 성능은 불리 |
| Protobuf | 바이너리 직렬화 | 빠르고 용량 작음 | 관리 복잡 |
| Avro | 바이너리 직렬화 | 대용량 데이터 처리에 유리 | 일반 서비스에서는 자주 사용하지 않음 |
| DB | 데이터 관리 시스템 | 실무 표준, 검색/수정/삭제 용이 | 별도 학습과 관리 필요 |

---

# 실무에서는?

일반적인 웹 서비스나 API 통신에서는 JSON을 많이 사용한다.

이유

- 사람이 읽기 쉽다.
- 다양한 언어에서 지원한다.
- 관리와 유지보수가 쉽다.
- 웹 API 표준처럼 널리 사용된다.

성능 최적화가 매우 중요한 경우에는  
Protobuf나 Avro 같은 바이너리 포맷을 고려할 수 있다.

회원 정보처럼 영구적으로 보관해야 하는 데이터는  
실무에서 대부분 데이터베이스에 저장한다.

---

# 핵심 정리

1. 메모리 저장은 빠르고 단순하지만 프로그램 종료 시 데이터가 사라진다.
2. 파일 저장은 데이터를 영구 보관할 수 있지만 직접 관리해야 한다.
3. DataStream은 기본 타입 데이터를 편리하게 저장하고 읽을 수 있다.
4. DataStream은 저장 순서와 읽는 순서가 같아야 한다.
5. ObjectStream은 객체 자체를 저장하고 읽을 수 있다.
6. ObjectStream을 사용하려면 Serializable을 구현해야 한다.
7. ObjectStream은 자바 중심 방식이라 호환성과 유지보수에 주의해야 한다.
8. XML은 태그 기반 포맷이고 과거에 많이 사용되었다.
9. JSON은 현재 가장 많이 사용되는 데이터 포맷이다.
10. JSON은 관리와 유지보수가 쉽다.
11. Protobuf와 Avro는 성능 최적화가 중요할 때 고려할 수 있다.
12. 실무에서 영구 데이터 저장은 대부분 데이터베이스를 사용한다.
