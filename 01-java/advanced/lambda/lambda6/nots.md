# Lambda vs Anonymous Class

## 람다와 익명 클래스

람다와 익명 클래스는 둘 다 이름 없는 구현체를 만들 때 사용할 수 있다.

둘 다 함수형 인터페이스를 구현해서  
동작을 전달하는 방식으로 사용할 수 있다.

하지만 사용 목적과 특징에는 차이가 있다.

---

# 익명 클래스

익명 클래스는 이름이 없는 클래스를 즉석에서 만들어 사용하는 방식이다.

클래스를 따로 만들지 않고  
인터페이스나 추상 클래스를 바로 구현할 수 있다.

---

## 익명 클래스 예시

interface Procedure {
    void run();
}

Procedure procedure = new Procedure() {
    @Override
    public void run() {
        System.out.println("익명 클래스 실행");
    }
};

procedure.run();

---

## 익명 클래스 특징

- 이름 없는 클래스를 만든다.
- 인터페이스를 구현할 수 있다.
- 추상 클래스를 상속할 수 있다.
- 메서드를 오버라이딩할 수 있다.
- 내부에 필드나 추가 메서드를 가질 수 있다.
- 복잡한 로직을 작성할 때 람다보다 명확할 수 있다.

---

# 람다

람다는 함수형 인터페이스를 간결하게 구현하는 문법이다.

익명 클래스보다 짧고 간단하게 동작을 표현할 수 있다.

---

## 람다 예시

interface Procedure {
    void run();
}

Procedure procedure = () -> System.out.println("람다 실행");

procedure.run();

---

## 람다 특징

- 함수형 인터페이스에만 사용할 수 있다.
- 추상 메서드가 하나인 인터페이스에만 사용 가능하다.
- 코드가 짧고 간결하다.
- 동작을 값처럼 전달할 수 있다.
- filter, map, reduce 같은 함수형 스타일에 잘 어울린다.

---

# 함수형 인터페이스 필요 여부

람다는 반드시 함수형 인터페이스가 필요하다.

함수형 인터페이스는 추상 메서드가 하나만 있는 인터페이스이다.

예시

@FunctionalInterface
interface MyFunction {
    int apply(int value);
}

람다 사용

MyFunction function = value -> value * 2;

---

## 익명 클래스는 더 넓게 사용할 수 있다

익명 클래스는 함수형 인터페이스뿐만 아니라  
일반 인터페이스나 추상 클래스에도 사용할 수 있다.

즉, 람다보다 사용할 수 있는 범위가 넓다.

---

# 람다와 익명 클래스 비교

| 구분 | 람다 | 익명 클래스 |
|------|------|-------------|
| 사용 대상 | 함수형 인터페이스 | 인터페이스, 추상 클래스 |
| 코드 길이 | 짧고 간결함 | 상대적으로 김 |
| 추상 메서드 개수 | 1개만 가능 | 여러 메서드 구현 가능 |
| 필드 선언 | 불가 | 가능 |
| 추가 메서드 선언 | 불가 | 가능 |
| this 의미 | 바깥 객체 | 익명 클래스 객체 |
| 적합한 상황 | 단순한 동작 전달 | 복잡한 로직 또는 상태 필요 |

---

# 람다를 사용하는 경우

람다는 간단한 동작을 전달할 때 사용하기 좋다.

사용하기 좋은 경우

- 코드가 짧을 때
- 로직이 단순할 때
- 함수형 인터페이스를 사용할 때
- 조건, 변환, 소비 같은 동작을 전달할 때
- filter, map, reduce 같은 함수형 처리에서 사용할 때

---

## 람다 사용 예시

List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> result = numbers.stream()
        .filter(value -> value % 2 == 0)
        .map(value -> value * 2)
        .toList();

의미

1. 짝수만 필터링한다.
2. 각 값을 2배로 변환한다.
3. 리스트로 반환한다.

---

# 익명 클래스를 사용하는 경우

익명 클래스는 람다보다 코드가 길지만  
복잡한 로직을 작성할 때 더 명확할 수 있다.

사용하기 좋은 경우

- 로직이 복잡할 때
- 여러 메서드를 오버라이딩해야 할 때
- 내부 상태를 가져야 할 때
- 필드가 필요할 때
- this가 익명 클래스 자신을 가리켜야 할 때
- 추상 클래스를 상속해야 할 때

---

## 익명 클래스 사용 예시

Comparator<String> comparator = new Comparator<String>() {

    @Override
    public int compare(String o1, String o2) {
        System.out.println("문자열 길이 비교");
        return o1.length() - o2.length();
    }
};

---

# 람다로 변경

위 익명 클래스는 함수형 인터페이스이므로 람다로 변경할 수 있다.

Comparator<String> comparator =
        (o1, o2) -> o1.length() - o2.length();

람다를 사용하면 코드가 훨씬 간결해진다.

---

# this 차이

람다와 익명 클래스는 this가 가리키는 대상이 다르다.

---

## 람다의 this

람다에서 this는 람다를 감싸고 있는 바깥 객체를 의미한다.

즉, 람다 자체는 별도의 this를 가지지 않는다.

---

## 익명 클래스의 this

익명 클래스에서 this는 익명 클래스 객체 자신을 의미한다.

즉, 익명 클래스는 실제로 이름 없는 클래스를 하나 만드는 것이기 때문에  
자기 자신을 가리키는 this가 존재한다.

---

## this 차이 정리

| 구분 | this 의미 |
|------|-----------|
| 람다 | 바깥 객체 |
| 익명 클래스 | 익명 클래스 객체 자신 |

---

# 변수 캡처

람다와 익명 클래스는 외부 지역 변수를 사용할 수 있다.

하지만 사용하는 지역 변수는 final 또는 effectively final이어야 한다.

---

## effectively final

명시적으로 final을 붙이지 않았지만  
값이 한 번만 대입되고 변경되지 않는 변수를 의미한다.

예시

int number = 10;

Runnable runnable = () -> System.out.println(number);

number 값이 이후에 변경되지 않으면 사용할 수 있다.

---

## 변수 캡처 주의점

아래처럼 지역 변수를 변경하면 사용할 수 없다.

int number = 10;

Runnable runnable = () -> System.out.println(number);

number = 20;

이 경우 number가 effectively final이 아니므로 컴파일 오류가 발생한다.

---

# 람다와 익명 클래스의 활용 방식

## 람다 활용

람다는 동작을 간단하게 전달할 때 사용한다.

예시

button.setOnClickListener(event -> save());

list.stream()
        .filter(value -> value > 10)
        .map(value -> value * 2)
        .toList();

특징

- 짧은 동작 표현
- 조건 전달
- 변환 로직 전달
- 콜백 전달
- 함수형 프로그래밍 스타일

---

## 익명 클래스 활용

익명 클래스는 즉석에서 클래스를 만들어야 할 때 사용한다.

예시

Runnable runnable = new Runnable() {

    private int count = 0;

    @Override
    public void run() {
        count++;
        System.out.println("count = " + count);
    }
};

특징

- 내부 상태 보관 가능
- 필드 사용 가능
- 여러 줄의 복잡한 로직 작성 가능
- 여러 메서드 오버라이딩 가능
- 추상 클래스 구현 가능

---

# 람다를 선택하는 기준

람다를 사용하면 좋은 경우

- 구현해야 할 메서드가 하나이다.
- 로직이 짧다.
- 한 줄 또는 몇 줄로 표현 가능하다.
- 의도가 명확하다.
- 함수형 인터페이스를 사용한다.

예시

Predicate<Integer> predicate = value -> value > 10;

Function<String, Integer> function = value -> value.length();

Consumer<String> consumer = value -> System.out.println(value);

---

# 익명 클래스를 선택하는 기준

익명 클래스를 사용하면 좋은 경우

- 로직이 복잡하다.
- 내부 상태가 필요하다.
- 필드나 추가 메서드가 필요하다.
- 여러 메서드를 오버라이딩해야 한다.
- this가 익명 클래스 자신을 가리켜야 한다.
- 추상 클래스를 구현해야 한다.

---

# 람다와 익명 클래스 선택 가이드

| 상황 | 추천 |
|------|------|
| 간단한 조건 전달 | 람다 |
| 간단한 변환 로직 | 람다 |
| 간단한 실행 로직 | 람다 |
| filter, map, reduce | 람다 |
| 로직이 길고 복잡함 | 익명 클래스 또는 별도 클래스 |
| 내부 상태 필요 | 익명 클래스 |
| 여러 메서드 구현 필요 | 익명 클래스 |
| 추상 클래스 상속 필요 | 익명 클래스 |
| 재사용이 많이 필요 | 별도 클래스 |

---

# 중요한 관점

람다는 익명 클래스를 완전히 대체하는 것이 아니다.

람다는 함수형 인터페이스를 간결하게 구현하기 위한 문법이다.

간단한 동작은 람다로 표현하는 것이 좋고,  
복잡한 로직은 익명 클래스나 별도 클래스로 분리하는 것이 좋다.

---

# 실무에서의 사용 기준

실무에서는 단순한 콜백, 조건, 변환 로직은 람다를 많이 사용한다.

하지만 람다 안에 너무 많은 코드가 들어가면  
오히려 가독성이 떨어진다.

따라서 람다는 짧고 명확하게 사용하는 것이 좋다.

복잡한 로직은

- 익명 클래스
- 별도 메서드
- 별도 클래스

로 분리하는 것이 유지보수에 좋다.

---

# 핵심 정리

1. 람다와 익명 클래스는 모두 동작을 전달할 때 사용할 수 있다.
2. 람다는 함수형 인터페이스에만 사용할 수 있다.
3. 익명 클래스는 인터페이스 구현이나 추상 클래스 상속에 사용할 수 있다.
4. 람다는 코드가 짧고 간결하다.
5. 익명 클래스는 필드나 추가 메서드를 가질 수 있다.
6. 람다의 this는 바깥 객체를 가리킨다.
7. 익명 클래스의 this는 익명 클래스 객체 자신을 가리킨다.
8. 람다와 익명 클래스 모두 외부 지역 변수는 final 또는 effectively final이어야 사용할 수 있다.
9. 간단한 로직은 람다가 적합하다.
10. 복잡한 로직이나 내부 상태가 필요한 경우 익명 클래스가 적합할 수 있다.
11. 재사용이 많고 로직이 크다면 익명 클래스보다 별도 클래스로 분리하는 것이 좋다.
12. 람다는 익명 클래스를 완전히 대체하는 것이 아니라, 함수형 인터페이스 구현을 간결하게 만드는 문법이다.
